### 何时使用

当登录、注册、提交评论、发送短信验证码、敏感操作确认等流程需要区分真人操作与自动化请求时，可使用滑块拼图验证码。验证码应作为风险控制的补充校验，避免在低风险、频繁操作链路中反复打断用户。

### 常见用法

##### 基础滑块拼图

用户拖动滑块，使真实图片拼图块移动到背景图中的目标缺口位置。拼图块应来自服务端返回的透明图片，或由运行时 canvas 从背景图裁剪得到；样式层只负责承载图片、同步位移和展示状态，不用 CSS 绘制假的拼图形状。

##### 带缺口图片

背景图建议在生成阶段已经包含目标缺口、阴影或遮罩，前端仅根据服务端返回的 `targetLeft`、`targetTop` 展示目标区域。这样可以保证缺口、拼图块和校验坐标来自同一份素材，避免视觉与校验结果不一致。

##### 保持配置自由度

不要把缺口数量、通过误差或校验策略固化在样式层。单缺口、多缺口、不同拼图尺寸、不同误差阈值都应由组件属性或服务端 challenge 数据描述，前端样式只提供可组合的目标区域、真实拼图块和状态反馈。

##### 刷新与重试

验证码加载失败、验证失败或过期时，应保留刷新入口。刷新后需要重新拉取背景图、拼图块、验证码 token 和目标位置信息，不能复用上一次挑战数据。

### 推荐/慎用示例

##### 推荐

| 场景              | 说明                                                   |
| ----------------- | ------------------------------------------------------ |
| 使用真实裁剪图块  | 拼图块纹理与背景图一致，用户能明确判断目标位置。       |
| 服务端校验结果    | 前端提交拖动距离、轨迹和 token，由服务端判断是否通过。 |
| 成功/失败反馈明确 | 验证通过后进入下一步，验证失败时提示重试并支持刷新。   |

##### 慎用

| 场景                               | 风险                                                 |
| ---------------------------------- | ---------------------------------------------------- |
| 用 CSS 画一个固定色块充当拼图块    | 拖动对象不是图片的一部分，视觉上不符合滑动拼图逻辑。 |
| 仅在客户端判断拖动距离             | 通过条件容易暴露，不能作为可靠的安全校验。           |
| 缺口、拼图块、校验坐标来自不同来源 | 可能出现用户视觉上对齐但校验失败的情况。             |

### 组件搭配使用

验证码通常与登录表单、注册表单、二次确认弹窗、短信验证码发送按钮搭配使用。建议在用户触发高风险操作后再展示，避免页面初始化时直接阻塞主流程。
