## Code Demo

### 01 Component Type

#### Basic slide puzzle

Drag the slider with touch interaction and move the real image puzzle piece to the target cutout to complete verification.

{{ base }}

#### Custom image

Use custom background image, puzzle image, and cutout position to connect with verification assets generated by your business service. Prefer a background image that already includes the target cutout or mask. The draggable piece should be a transparent PNG returned by the server, or a real image block clipped from the background with canvas at runtime. The style layer only hosts `img` / `canvas` / `--td-captcha-piece-image`; it should not draw a fake puzzle piece with CSS. The target cutout and the initial draggable piece position are controlled separately by `--td-captcha-target-left/top` and `--td-captcha-piece-left/top`.

{{ customImage }}

#### Flexible configuration

The number of cutouts, target coordinates, puzzle assets, tolerance, drag trail, and verification strategy should be defined by the framework component or server-side challenge data. The common style layer should not hard-code these rules. A single cutout can be positioned with `--td-captcha-target-left/top/width/height` and `--td-captcha-piece-left/top/width/height`. For multiple cutouts, support them by rendering multiple `.t-captcha__cutout` and `.t-captcha__piece` nodes, and assign independent CSS variables and image assets to each node. The tolerance can be used for frontend touch interaction feedback, but the final result should still come from server-side verification.
